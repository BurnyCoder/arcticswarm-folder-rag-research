**In plain language:**
- **News questions (MultiHop-RAG, 10 questions).** The swarm (M) and the single agent (B2) both answered {{summary.M.mhr_judge_acc|pct}} correctly. They got exactly the same questions right, so there was no gain from multiple agents.
  - Both nearly always found the right source files: gold-evidence recall was {{summary.M.mhr_evidence_recall|pct}} for M and {{summary.B2.mhr_evidence_recall|pct}} for B2.
  - The misses came from wrong final verdicts, not missing evidence.
- **Code questions (SWE-QA, 10 questions over requests/flask/pytest/django).**
  - The swarm scored **worse**: {{summary.M.swe_mean|f1}}/100 against {{summary.B2.swe_mean|f1}}/100. The difference is {{tests.H3.diff|f1}}, 95% CI {{tests.H3.ci|f1ci}}, Holm p = {{tests.H3.p_holm|f3}}.
  - That difference is statistically significant **against** the pre-registered hypothesis, so it is a negative result for the swarm.
  - Exploratory: the swarm's answers were much longer (median {{summary.M.resp_chars_median_swe|int}} vs {{summary.B2.resp_chars_median_swe|int}} characters), and the strict rubric penalised them mostly on clarity and relevance.
- **Cost and speed.**
  - The swarm costs {{summary.M.cost_usd_per_q|usd}} per question against {{summary.B2.cost_usd_per_q|usd}}, which is {{ratios.cost_M_over_B2|f1}}× more.
  - It takes {{summary.M.latency_s_median|int}} s against {{summary.B2.latency_s_median|int}} s (median).
- **How many agents?** We ran the swarm with caps of 2, 4, 8, 16 and 32 agents, plus the single agent (1). Cap 16 is ArcticSwarm's default, so the main-method run M is the cap-16 arm.
  - With 2 or 4 agents, many questions ran into the 15-minute limit: {{summary.M_cap2.hit_time_limit|int}} for cap 2 and {{summary.M_cap4.hit_time_limit|int}} for cap 4, against {{summary.M.hit_time_limit|int}} for cap 16. The orchestrator plans for about 6–9 agents, so with fewer its tasks queue.
  - MultiHop-RAG accuracy by cap: 2 → {{summary.M_cap2.mhr_judge_acc|pct}}, 4 → {{summary.M_cap4.mhr_judge_acc|pct}}, 8 → {{summary.M_cap8.mhr_judge_acc|pct}}, 16 → {{summary.M.mhr_judge_acc|pct}}, 32 → {{summary.M_cap32.mhr_judge_acc|pct}}.
  - SWE-QA score by cap: 2 → {{summary.M_cap2.swe_mean|f1}}, 4 → {{summary.M_cap4.swe_mean|f1}}, 8 → {{summary.M_cap8.swe_mean|f1}}, 16 → {{summary.M.swe_mean|f1}}, 32 → {{summary.M_cap32.swe_mean|f1}}.
  - **No swarm size beat the single agent** on SWE-QA. The best swarm, cap 32, scored {{summary.M_cap32.swe_mean|f1}} against {{summary.B2.swe_mean|f1}}. On MultiHop-RAG all arms were within noise of each other.
  - Caps of 8 or more don't change anything, because the orchestrator only spawns about 6–7 agents. By the pre-registered rule (the cheapest arm whose quality CI overlaps the best), the **optimal number of agents here is 1**.
  - Details: [reports/experiments/day1-agent-sweep.md](reports/experiments/day1-agent-sweep.md).
- **Metric sanity check.** Under MultiHop-RAG's official word-overlap metric, a constant string scores {{trivial_baselines.constant_hedge.official_overlap|pct1}}. We therefore score a forced `FINAL ANSWER:` line with a strict judge, and report exact match alongside.
- **Caveat.** n = 10 per dataset, a single run, and an LLM judge from the same model family. Treat these as narrow, preliminary findings for this configuration.
